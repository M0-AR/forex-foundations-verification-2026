# Screenshots — how they are made (Playwright, reproducible)

Best practice applied: full-page captures stored **in the repo** (`docs/screenshots/`),
desktop `1440×900` + mobile `390×844`, regenerated with one command. No external
image host (hosts die; the repo does not).

## Regenerate

```bash
# install once
pip install playwright
python -m playwright install chromium --with-deps

# capture preview.html (file:// URL, no server needed)
python scripts/shot_preview.py
# outputs:
#   docs/screenshots/preview-desktop.png
#   docs/screenshots/preview-mobile.png
#   docs/screenshots/preview-full.png
```

`scripts/shot_preview.py` uses Playwright headless Chromium, waits for
`domcontentloaded` + 800ms, disables animations for determinism, and captures
viewport + fullPage. The same approach powers `docs-html-screenshot` style CI:
fail on missing images, upload PNGs as artefacts.

## Demo video vs GIF

- README files play **GIFs** inline; `<video>` tags are stripped. So the animated
  README demo is `assets/demo.gif` (generated by `scripts/make_demo_gif.py` from
  `results/benchmark.json` — no hand numbers, keep under ~8 MB).
- For narrated video: record once (terminal `make verify` + scroll of
  `preview.html`), upload to YouTube, and embed the **clickable thumbnail**
  pattern in the README (image linking to the video URL). See README §Demo.
